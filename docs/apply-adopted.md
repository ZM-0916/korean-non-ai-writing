# 채택 항목 반영 절차

매일 실행되는 반영 작업이 이 문서를 읽고 따른다. 메인테이너가 `채택` 라벨을 붙인 이슈만 반영한다.

## 대상 확인

1. 열린 이슈 중 `채택` 라벨이 붙은 것을 모은다.
2. 이슈마다 라벨을 붙인 사람을 확인한다(이슈 이벤트 API의 `labeled` 이벤트, `actor`). 메인테이너 `ZM-0916`이 붙인 경우만 반영한다. 다른 사람이 붙였으면 건너뛰고 이슈에 그 사실을 댓글로 남긴다.
3. `자동 수집` 이슈는 표의 행마다 `채택` 댓글을 메인테이너가 달았는지 확인한다. 이슈 전체에 `채택` 라벨이 있으면 모든 행을 반영한다.

## 반영

이슈 종류에 따라 고친다.

| 이슈 | 고칠 곳 |
|---|---|
| 표현 사전 후보(자동 수집 포함) | `references/lexicon.md`에 행 추가. 상태는 `확정`. 가나다순 정렬 |
| 새 패턴 | `SKILL.md` §4 해당 범주, 가능하면 `scripts/scan.py`의 `RULES` |
| Claude 말버릇 | `SKILL.md` §4 L 범주. 처음이면 `후보`, 이미 후보면 `확정` |
| 오탐 | 해당 패턴의 예외 문구, `scan.py` 정규식, `tests/fixtures`에 걸리면 안 되는 문장 추가 |

반영할 때마다 테스트 문장을 하나 이상 추가한다. 걸려야 하는 표현은 `must_detect` 또는 `must_flag`, 걸리면 안 되는 표현은 `must_not_flag`에 넣는다.

## 버전과 기록

- 패치 버전을 올린다(예: 0.3.0 → 0.3.1). 패턴 추가, 삭제, 심각도 변경이 있으면 마이너 버전을 올린다.
- 네 곳을 같은 버전으로 맞춘다: `SKILL.md`의 버전 줄, `.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json`, `CHANGELOG.md` 최상단.
- CHANGELOG에 반영한 이슈 번호를 적는다.

## 검증과 푸시

1. `python3 tests/run_tests.py`가 전부 PASS여야 한다.
2. 실패하면 푸시하지 않는다. 실패 내용을 해당 이슈에 댓글로 남기고 끝낸다.
3. 통과하면 main에 커밋하고 푸시한다. 커밋 메시지에 이슈 번호를 적는다.
4. 반영한 이슈에 반영 버전을 댓글로 남기고 닫는다.

## 하지 않는 것

- `채택`이 없는 이슈 반영
- 테스트 실패 상태로 푸시
- 이슈에 없는 규칙을 임의로 추가
- 엠대시, 엔대시, 중앙점 사용(파일, 커밋 메시지, 댓글 모두)
